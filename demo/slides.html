guidemd

Executable, dimension-aware guides for llm-d

One authored markdown file per guide →

  • an interactive page with configuration pickers (llm-d.ai)
  • a readable GitHub copy — default path expanded with real values, alternatives collapsed
  • an executable CI run for every tested configuration

Derived, never duplicated — so they can't drift. (→ / ← to navigate)

The problem

  • A guide varies along 7 dimensions: infra provider, router mode, gateway provider, accelerator, model server, model, monitoring — one of them hiding in an env-var comment (export PROVIDER_NAME=gke # options: …)
  • Today: one monolithic README — "comment out the above and uncomment the below" — readers execute the branching in their heads
  • CI scrapes bash out of prose → docs and CI drift
  • Prereqs / verification / benchmark sections copy-pasted across guides

Requirements

Reader interactive, contextual guide — pickers in dimension order, invalid combos unselectable, deep-linkable URLs — AND still readable on GitHub / local editor with no tooling
CI/CD derive an executable, verifiable run for any supported combination — docs and CI can never drift; dry-run affordable on every PR (no cluster needed), full e2e on the tested matrix
Writer plain markdown stays valid (adopt incrementally, experiment freely); common sections maintained once, imported everywhere

Design principles

1 · One authored source. Exactly one guide.template.md per guide — no forks per dimension value.
2 · Everything else is generated. Readers and CI consume derived artifacts; the PR gate blocks drift.
3 · Explicitly executable. A step marker is how CI finds scripts; an unmarked bash block fails validation; metadata keys are declared — a typo'd tag is an error, not a silent CI change.
4 · CI is just a special user. It runs steps top to bottom like a human; dry-run vs e2e are just different users skipping different opaque tags.
5 · Constraints, not enumeration. Ordered dimensions + 7 rules: 672 combos → 96 valid → 8 tested. Supported ≠ tested — the page shows which one you picked.
6 · Compose, don't copy. Shared sections are imported fragments with parameters; fragments import fragments.
7 · Plain markdown is still a guide. Zero annotations = valid guide; adopt incrementally, experiment freely.
8 · Dimensions serve both sides. Writers own a dimension in isolation; readers get a contextual guide with zero distraction.

Three personas, one source

PersonaTouchesGets
Writer plain markdown + two statements (when, import) a thin guide: env choices + 6 import lines + prose
Reader readonly-guide.html / readonly-guide.md pickers in dimension order, deep links, ✓ CI-tested / ⚠ supported per variant · GitHub copy with collapsible alternatives
CI plan --set dim=value … --format yaml|bash an executable, verifiable run — exactly what a human would type; every step cites its source file:line

Multiple writers: fragments + when regions map ownership to files → CODEOWNERS.

The entire syntax

<!-- when accelerator=gpu model=Qwen/Qwen3-32B -->   conditional region; nestable
…prose and/or code…                                  k=v1|v2 for multi-value
<!-- end -->

<!-- import ../common/verify.md key=value -->        shared fragment, one line

<!-- step -->                                        next ```bash fence is a step
<!-- step ci=skip -->                                metadata: values opaque,
                                                     keys declared in step_tags:
<!-- step e2e=skip hide=true -->                     hidden dry-run stand-in

<!-- badges -->                                      E2E badges derived from ci: rows
{{ accelerator }}                                    the picked value, inline

No section schema. No phases. No step ids — a deliberate trade-off (no resume-from-step); optional stable ids are the designed escape hatch if flake tracking ever needs them.

Dimensions: pick in order, constrain by rule

dimensions:                        # declaration order = pick order
  infra_provider:   { values: [base, gke] }
  router_mode:      { values: [standalone, gateway] }
  gateway_provider: { values: [none, gke, istio, agentgateway] }
  accelerator:      { values: [gpu, amd, xpu, hpu, tpu/v6, tpu/v7, cpu] }
  model_server:     { values: [vllm, sglang, trtllm] }
  model:            { values: [Qwen/Qwen3-32B, openai/gpt-oss-120b] }
  monitoring:       { values: ["off", "on"] }
rules:                             # earlier dims narrow later dims
  - when:  { router_mode: standalone }
    allow: { gateway_provider: [none] }
  - when:  { infra_provider: gke }
    allow: { accelerator: [gpu, tpu/v6, tpu/v7] }
ci:        # tested cells; badge:/workflow: rows also generate the E2E badges
  - { infra_provider: gke, …, badge: E2E (GKE TPU v6e), workflow: …-x.yaml }

672 raw combinations → 96 valid → 8 CI jobs. What used to be an env-var comment is a dimension — rules, not comments, forbid incoherent mixes (GKE gateway class on a non-GKE cluster).

Derived artifacts

guide.template.md ──┬── render-md ───▶ readonly-guide.md    committed GitHub copy
(authored source)   ├── render-html ─▶ readonly-guide.html  interactive picker page
                    ├── plan ────────▶ yaml / bash          executable CI run
                    ├── matrix ──────▶ ci cells             the CI job matrix
                    └── validate ────▶ pass / fail          PR gate (+ warnings)
# every PR (cheap): dry-run — env wiring, helm template, kustomize build.
# Touches NO cluster: runs on any PR runner with zero credentials.
guidemd.py plan guide.template.md --set … --skip ci=skip --skip dry-run=skip | bash

# nightly / matrix (real): e2e — installs, waits, asserted verification, benchmark
guidemd.py plan guide.template.md --set … --skip ci=skip --skip e2e=skip | bash

Steps default to both; dry-run=skip marks real-world steps, e2e=skip hide=true their hidden stand-ins. Verification is asserted, not eyeballed: curl -fsS + jq -e fail the run unless the router returns a real completion.

Guardrails — what the gate catches

  • Errors: stale readonly-guide.md · unmarked bash fence · undeclared step tag (dry-run=skpi) · unresolved import param · untested/incomplete ci: row
  • Warnings: dead when region (no supported combo can enter) · a when-group that leaves some combo matching no branch — the "add a value later, silently lose commands" trap · validate --cells prints per-variant step counts
  • Every diagnostic names the real file:line — through import expansion, so an error inside a shared fragment points at the fragment
  • Coverage gate vs the upstream guide: 63/88 items verbatim, 25 reviewed waivers, 0 missing — "no loss of information", enforced, with stale waivers flagged too
  • 24 tests over all 96 variants: placeholder-free renders, bash -n-valid plans, cluster-free dry-runs
