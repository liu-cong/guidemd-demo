guidemd

Executable, dimension-aware guides for llm-d

One authored markdown file per guide →

  • an interactive page with configuration pickers (llm-d.ai)
  • a readable GitHub copy — default path expanded, alternatives collapsed
  • an executable CI run for every tested configuration

Derived, never duplicated — so they can't drift. (→ / ← to navigate)

The problem

  • A guide varies along 6 dimensions: infra provider, router mode, accelerator, model server, model, monitoring
  • Today: one monolithic README — "comment out the above and uncomment the below" — readers execute the branching in their heads
  • CI scrapes bash out of prose → docs and CI drift
  • Prereqs / verification / benchmark sections copy-pasted across guides

Design principles

1 · One authored source. Exactly one guide.template.md per guide — no forks per dimension value.
2 · Everything else is generated. Readers and CI consume derived artifacts; the PR gate blocks drift.
3 · Explicitly executable. A step marker is how CI finds scripts; an unmarked bash block fails validation.
4 · CI is just a special user. It runs steps top to bottom like a human; dry-run vs e2e are just different users skipping different opaque tags.
5 · Constraints, not enumeration. Ordered dimensions + 4 rules: 336 combos → 56 valid → 8 tested.
6 · Compose, don't copy. Shared sections are imported fragments with parameters.
7 · Plain markdown is still a guide. Zero annotations = valid guide; adopt incrementally, experiment freely.
8 · Dimensions serve both sides. Writers own a dimension in isolation; readers get a contextual guide with zero distraction.

Three personas, one source

PersonaTouchesGets
Writer plain markdown + two statements (when, import) a thin guide: env choices + 6 import lines + prose
Reader readonly-guide.html / readonly-guide.md pickers in dimension order, deep links · GitHub copy with collapsible alternatives
CI plan --set dim=value … --format yaml|bash an executable, verifiable run — exactly what a human would type

Multiple writers: fragments + when regions map ownership to files → CODEOWNERS.

The entire syntax

<!-- when accelerator=gpu model=Qwen/Qwen3-32B -->   conditional region; nestable
…prose and/or code…                                  k=v1|v2 for multi-value
<!-- end -->

<!-- import ../common/verify.md key=value -->        shared fragment, one line

<!-- step -->                                        next ```bash fence is a step
<!-- step ci=skip anything=else -->                  …optional opaque metadata

{{ accelerator }}                                    the picked value, inline

No section schema. No phases. No step ids. Steps run in document order — like a human reading the page.

Dimensions: pick in order, constrain by rule

dimensions:                      # declaration order = pick order
  infra_provider: { values: [base, gke] }
  router_mode:    { values: [standalone, gateway] }
  accelerator:    { values: [gpu, amd, xpu, hpu, tpu/v6, tpu/v7, cpu] }
  model_server:   { values: [vllm, sglang, trtllm] }
  model:          { values: [Qwen/Qwen3-32B, openai/gpt-oss-120b] }
  monitoring:     { values: ["off", "on"] }
rules:                           # earlier dims narrow later dims
  - when:  { infra_provider: gke }
    allow: { accelerator: [gpu, tpu/v6, tpu/v7] }
ci:                              # tested cells: complete flattened rows
  - { infra_provider: gke, router_mode: standalone, accelerator: tpu/v6, … }

336 raw combinations → 56 valid → 8 CI jobs. Invalid combos are unselectable in the UI and rejected by plan.

Derived artifacts

guide.template.md ──┬── render-md ───▶ readonly-guide.md    committed GitHub copy
(authored source)   ├── render-html ─▶ readonly-guide.html  interactive picker page
                    ├── plan ────────▶ yaml / bash          executable CI run
                    ├── matrix ──────▶ ci cells             the CI job matrix
                    └── validate ────▶ pass / fail          PR gate (drift = red)
# every PR (cheap): dry-run — env wiring, helm template, kustomize build
guidemd.py plan guide.template.md --set … --skip ci=skip --skip dry-run=skip | bash

# nightly / matrix (real): e2e — installs, waits, verification, benchmark
guidemd.py plan guide.template.md --set … --skip ci=skip --skip e2e=skip | bash

Steps default to both; dry-run=skip marks real-world steps, e2e=skip hide=true marks their hidden dry-run stand-ins (helm template, kubectl kustomize) — in every plan, invisible to readers.

Live demo

  • Reader: open readonly-guide.html — pick gke → accelerator menu narrows to gpu/tpu; pick trtllm → the router values swap; URL is shareable
  • GitHub: readonly-guide.md — default path linear, 10 Alternative sections collapsed
  • Writer: guide.template.md — 6 import lines; the helm/kubectl mechanics live once in guides/common/
  • CI: plan … --format yaml — structured steps with opaque metadata; matrix --github — the 8 tested cells
